## 自动化与构建

在项目独立的 `.venv` 中运行 `python -m pytest -q`，21 项全部通过。依赖包另有一条测试客户端未来迁移的弃用提示，不影响运行。测试覆盖：

- 共享回合快照下，互不冲突的行动均可提交；争抢同一物品只有一人成功。
- 私语只投递参与者；旁观者的模型上下文无法看到秘密或其他人的私有目标。
- 声称已交付音箱、已分配摊位、已获胜，不会自动改变世界事实。
- 非法行动回滚，重复请求和重复裁决不重复执行。
- 最后一回合安装音箱可获胜，条件不足时由代码在期限结束后判负。
- 安全检查仅管理员可做，累计需要两个工作行动；免费观察不推进回合。
- 无模型规则演示可完整开幕；未完成回合可恢复，已保存决策不会重复执行。
- 模拟模型服务验证合法行动与用量、非法 JSON、不可见事件引用、超时和迟到结果。
- HTTP 新建、动作、存档、重开、配置密钥不回传、调试关闭及本机请求边界。
- SSE 只推送玩家可见事件，并支持从事件游标续传。
- 角色简短行动意图保存为本人私有判断，其他角色和玩家无法读取。

前端执行 `npm run build`，包含 TypeScript 类型检查与 Vite 生产构建。

## 浏览器实际试玩

在 Windows 上使用实际 FastAPI 服务和生产前端进行操作：

1. 创建规则演示局，与镇长协商摊位，观察实际公告栏确认事件。
2. 免费观察后回合不变；沿地图移动到商店，与店主私语。
3. 检查服务端记录：店主收到私语，记者和镇长均未收到。
4. 刷新后恢复为第 3 回合、商店位置，原存档事件仍在。
5. 继续回合，实际在第 8 回合达成开幕条件并显示结算。
6. 打开世界档案，查看角色记忆、目标、决策与模型调用记录。
7. 新局修改店主目标，检查已写入该局角色配置；原存档继续保留。
8. 检查模型设置密码字段，不回显保存的密钥。
9. 在 1440 像素桌面与 390 像素手机宽度检查界面；手机无横向溢出。

浏览器发现地点标签被角色遮挡，已调整标签位置，并重新通过实际点击验证。

## 验证边界

已配置用户提供的兼容 API，模型为 `deepseek-v4.1-flash`，真实接口返回 HTTP 200，基础 JSON 请求约 1.7 秒。真实 AI 局连续两轮共八次角色决策均返回合法结构并通过世界规则裁决，单次约 2.3—8.0 秒。观察到镇长确认摊位、管理员开门和检查、记者采访、店主移动和对话。

另经 Cloudflare HTTPS 外网地址实际创建 AI 游戏并执行行动，能够读取完成后的回合与玩家事件。外网入口未带凭证返回 401，管理写入和调试返回 403，模型内部 API 地址不返回外网访客。分享入口的浏览器存档隔离、访问 cookie 和权限边界已加入测试。

这些验证覆盖当前端点的连接、结构化输出和短程实际行为，不代表长期稳定性或完整玩法平衡。价格和额度仍以模型服务商实际结算为准。
