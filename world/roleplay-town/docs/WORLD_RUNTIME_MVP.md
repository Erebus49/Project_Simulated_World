# 咖啡小镇基础 MVP

> 本页记录最初的调试网页。当前主入口已改为像素角色扮演，见 [新版说明](WORLD_RUNTIME_ROLEPLAY.md)；本文界面通过 `/?debug=1` 使用。模型配置现支持 `.env.runtime`，以新版说明为准。

当前分支：`refactor/world-runtime-v3`。按用户最新要求，优先交付可操作的网页，不再扩展测试矩阵。旧版游戏继续留在原目录和版本标签里。

## 启动

双击项目根目录 `start.bat`，或者执行：

```powershell
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:8011>。这是新的 Node.js 运行时，与旧 Python 游戏的 8000 端口分开。当前未将新版挂到原 Cloudflare 临时链接。

## 现在可用

- 默认 6 个角色，可选 3～8 个，三个地点：咖啡店、广场、集市。
- 开始、暂停、单步、重置；tick 和批次状态；WebSocket 更新。
- 角色移动、购买、工作、消息转述及等待；资金、咖啡、目标、收件和当前任务可查看。
- 传闻注入：选择接收人，下一控制边界投递。传闻不会直接改变真实价格。
- 发言规则开关及每日次数，下一边界生效，有 `rule_changed` 日志；超额由引擎拒绝，每 24 tick 重置。
- 时间线按事件序号显示，可筛选角色；点击消息可沿来源 ID 查看前序事件。
- 全知角色档案与“实际局部观察”分开显示。
- 导出整局 JSON；导入为只读回放，使用滑块查看已记录状态，不调用模型。
- Mock 模式无需密钥；有最简可配置模型适配器，但本轮网页演示只使用 Mock。

## 一分钟演示

1. 保持 Mock / 6 人，重置世界。
2. 向小满注入“明天咖啡可能涨价”。
3. 点单步：小满收到传闻并可选择转述；真实挂牌价仍是 6。
4. 点开始：两位顾客前往咖啡店并购买，店员与供应商工作。
5. 开启发言上限，改为 0 次，应用规则，再注入一条新消息；观察引擎拒绝超额消息或角色等待。
6. 暂停，点角色查看实际观察；点时间线里的消息逐级回看来源。
7. 导出运行，导入该 JSON，通过滑块回看，重置退出回放。

Mock 是确定性演示策略，不是假装真实 AI，也不保证传闻一定改变价格或传播给所有人。

## 可选真实模型

只读服务端环境变量，不从旧版 `backend/data/model.json` 读取或复制密钥：

```powershell
$env:MODEL_BASE_URL = 'https://your-provider.example/v1'
$env:MODEL_NAME = 'your-model-name'
$env:MODEL_API_KEY = 'your-key'
npm start
```

界面选择 AI 模式并重置后生效。当前适配 Chat Completions / JSON 对象输出；本地运行时始终执行结构校验与规则裁决。DeepSeek 关闭额外思考。尚未实现 429 重试、供应商专门适配和 token 统计；页面如实显示“未统计”。

## 本轮页面验证

生产构建通过；实际浏览器完成传闻注入、发言规则启用、单步、运行、暂停和角色观察查看。演示到 tick 6：库存从 12 到 10，成交 2 次，挂牌价仍为 6，成功发送消息 1 次。手机 390px 无横向溢出。

此前 P0 的内核测试在接网页前通过 35 项。本轮遵从用户要求没有继续扩测试或把这些旧结果描述为完整 MVP 已全部验收。新增服务、模型适配与导入界面仍是基础实现。

## 边界

这是本地单局原型：内存状态重启即清空，需手动导出保存；没有账号、多用户隔离或公开部署支持。所有网页信息明确为调试视角。导出包含角色私有目标和消息，密钥不在导出中。

引擎仍支持事件重建、取消与并发边界。界面先采用简单 DOM 场景，暂未把旧版 Kenney 地图接入咖啡场景。后续可以逐步美化和接真实模型，不影响目前用 Mock 操作完整闭环。
