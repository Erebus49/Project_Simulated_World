## 本轮具体实现

### 权威状态与事务

`EventJournal` 是状态持有者，内部使用 JavaScript 私有字段。外部只能取得深拷贝后冻结的快照。`WorldRuntime` 的执行器在候选状态应用效果，检查不变量，全部通过后替换权威状态并追加事件。

扣买家资金、加卖家资金、减少库存、增加咖啡物品在同一个候选事务内完成。越界资金与库存不会通过 min/max 截断伪装成功。工作收入明确记录为外源资金，日志中有 `workIncomeCreated`。

动作不是“说完就算执行”：只能提交注册的 `send_message / move / buy / set_price / work / wait`。未知动作、未知字段、角色身份注入、非法数值由 schema 拒绝，并记录后备等待。

### 三种边界

- **模拟 tick**：整数，只在明确 `step()` / `advance()` 中前进。
- **决策批次**：生成一次冻结快照，为本批所有角色构建观察；等待完成或期限后才结算，等待期间不推进 tick。
- **外部命令**：先进入引擎的暂存队列，不在批次中途污染观察；到下一个控制边界进入权威命令记录并应用。

`start()` 允许推进，但 P0 不隐式开启墙钟定时器。上层调用 `advance()` 推进；暂停时调用它不会前进。`step()` 要求暂停态，恰好前进一个 tick 并完成该 tick 的决策批次后回到暂停。

批次等待时调用 `pause()`，当前批次继续完成，随后暂停。`cancel()` 中止批次，不接受迟到动作。`reset()` 换运行代际和默认 runId，旧任务结果不能写入新局。重复调用 step/advance 开启并发批次会拒绝。

### 稳定结算

阶段固定为 **消息 → 资源 → 任务**。角色固定列表按 `(tick - 1) mod 角色数` 轮换，资源阶段的 set_price 与 buy 使用同一顺序。每个动作在实际提交前重新验证当前资源和价格。

所有模型结果先收集，再排序。因此同一意图集合交换响应延迟，最终世界和事件顺序保持一致。buy 必须提供 `maxUnitPrice`，不会因为同批先调价而意外接受任意价格。成交事件保留实际成交价。

### 局部认知和消息来源

角色观察只包含自己的人设、目标、资源、行动、收件和信念；附近角色只显示公共名字、ID、模式。咖啡挂牌价是本场景明确的公开事实，库存只有同地点可见。关系只用于直达消息，不泄露关系另一端的资金和私有目标。

消息发送在本批次记录，收件最早在下一 tick 控制边界进入收件人的知识。每条注入、发送、接收事件有稳定 ID。发送者在发出时看到发送事件，收件人只在收到时看到接收事件。转述引用接收事件，接收事件再引用前一条发送事件，可追溯到原始传闻。

所有引用必须是该角色已见且有权读取的事件；不能引用全知调试记录。原始注入标记为 rumor，信念标记 reported_claim；均不自动改挂牌价。角色观察不包含权威事件的 `differences`，因为差异可能含其他人的私有状态。

### 持续动作、唤醒和请求保护

移动、工作、等待是有上限的代码任务，到期再完成。执行期间不逐 tick 调用 Provider，收到消息只合并 dirtyReasons，不中断短任务。角色决策受冷却和整局预算限制。

为使 P0 的异步 Mock 也能验证生命周期，已包含基本并发槽位、单请求和整批期限。超时、异常、非法输出与预算不足使用确定性的 wait(1)，不执行重试。

若 Provider 无视 AbortSignal，它的未结束 Promise 仍占用真实槽位；不会因已显示超时而悄悄增加请求。其他角色继续降级等待。Provider 必须支持可取消 IO，才能实际释放这种占用；JavaScript 不能强制杀掉任意进程内代码。这种情况下 reset 也不会凭空取消真实在途请求。

### 事件日志与重建

每个提交记录递增事件号、run/tick/batch、可见范围、来源引用和必要状态差异。P0 差异按顶层字段保存 before/after，内容较粗但包含完整权威数据，适合小世界正确性验证。

`archive()` 返回内存中的初始状态、事件、最终状态；`replay(initialState, events)` 仅应用已记录差异并验证顺序与 before-state，不调用 Provider。测试包含任务队列、收件和信念的最终一致性，不只比较地图位置。

这是已记录结果的精确重建，不是再次让 Mock/模型决策。相同 Mock 重跑还另有全日志一致性测试。当前没有提供外部不可信 JSON 的导入接口、持久化落盘或只读回放 UI；这些属于 P3。

原始 archive/events 是全知调试数据，包含角色私有目标和消息，不应直接当作玩家接口暴露。密钥未进入本版配置、观察、事件或演示。

## 明确缺口与下一阶段

这轮交付 P0 可运行内核，不把它称为完整产品。

- **P1**：真实模型 Provider（仅服务端环境读 key）、429/有限重试/速率限制、模型 token 与延迟统计、进一步队列观测。当前没有真实 LLM，也没有这些网络回归测试。
- **P2**：Node HTTP + WebSocket 服务、React 控制台、角色观察/全知视角、消息链点击查看。当前只有命令行 demo。
- **P3**：同局 speech_limit 动态补丁及 effectiveTick、生效事件/唤醒、JSON 导入导出与只读回放 UI。P0 只硬校验初始化时的可选发言上限与模拟日重置，不提供动态改规则入口。
- 目前支持单动作，`plan` 留空，不实现长计划、复杂关系、生产供应链或协商交易。
- 输入与事件日志保留在内存，随着运行增长；复制与顶层差异以清晰和正确为先，不声称适合长期大规模世界。

现有旧版 Python 服务与 Cloudflare 链接仍运行旧版游戏。本轮没有将未完成的 P0 强行替换为网站，也没有重用旧密钥发起请求。
