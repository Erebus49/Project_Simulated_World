# 角色扮演前端：清晰文字与连续行走

当前预览：http://127.0.0.1:8011 。`npm run build` 构建，`npm start` 默认8010端口，可用 PORT 修改。本次更新前的运行记录备份在被 Git 忽略的 `data/runtime-before-phaser.json`，可在调试台导入查看。

## 画面分层

Phaser 4.2.1 管理游戏场景，优先 WebGL，无法创建 WebGL 时使用 Canvas 兼容画面。React 保留为已有 HTML/CSS 界面的状态层，不参与逐像素游戏渲染。

地图、人物和阴影绘制进 world RenderTexture，使用 NEAREST 采样和整数倍缩放。灯光单独绘制进 glow RenderTexture，使用 LINEAR 采样，由 `lighting.ts` 的 GLSL 合成。光照没有全局亮度呼吸或人物透明度闪烁。Phaser 4 的 RenderTexture 显式 render，避免队列未提交导致黑屏。

地图上的中文、英文副标与人物名字均是画布上方的 DOM 元素。世界坐标根据相机投影成整数屏幕坐标，字体不会经过低分辨率画布或光效通道。桌面路牌16px、人物名14px；小屏路牌14px、人物名13px，对话正文至少14px。

## 人物素材

`villagers.ts` 使用原创 ASCII 点阵头部、像素矩形、调色板与配饰生成24×32人物。玩家与六位居民有不同的发型、衣服、围裙、眼镜、相机、围巾。取消所有侧脸、背面和转头贴图，人物保持正面造型；行走六帧按实际行进距离换帧，腿和手臂改变姿势，另一行六帧播放擦杯子、翻教案、调整相机、核对货单或记笔记，不对整个人物做上下跳动或闪烁。头像来自同一生成器。

生成的 Canvas 通过 `textures.addCanvas()` 注册纹理，再切分为帧。人物纹理和 Sprite 每局只创建一次，普通模型状态、网络更新和区域变化都不会销毁人物实例。

## 连续移动

旧实现只绘制 nearby 角色，区域改变时删除缓存并在新区域生成，容易表现为闪现。新版服务器只补充可见户外区域的公开 appearance，包括最后一次实际 move 动作的标识、起点、终点、阶段；不会把人物的私有目标或模型输出放进该字段。

`TownScene.ts` 按角色ID维护 Sprite、最后已见位置、已处理动作ID、目标队列和当前路径。相同动作重复收到时不会重置行走。跨区时保留旧实例，走完路径后停止；暂时不可见时保留最后已知位置，不凭空获得隐藏状态。

`paths.ts` 采用有界 A*，避开建筑、水域和树木，禁止斜穿墙角，再用视线简化路径。角色以稳定速度行走，穿过中间路径点时消耗本步剩余距离，避免每个拐点停顿。转向只改变运动方向，不再改变人物外观。

移动逻辑固定60Hz，每帧最多补算5步；画面独立渲染，失焦清除按键与时间积累。角色跨区域的像素路程是动作的表现层，可能晚于逻辑 tick 完成，不承诺它与后端时间一一同步。

- `npm run build`：TypeScript 与生产构建通过。Phaser 独立打包，体积约1.68MB、gzip381KB，可被浏览器单独缓存。
- 实际浏览器 WebGL 场景可见，桌面走动、按 E 打开交谈、小屏对话均无页面脚本异常。
- 独立 Mock 局中，林岚从广场 (356,410) 走到咖啡店 (224,320)。连续30次采样，每次间隔约180ms：人物始终存在，Sprite 创建总数保持7，最大单次位置变化约6.8像素，结束后停在目的地；覆盖逻辑状态跨区完成时仍连续行走的情况。

## 日常活动与路牌稳定更新

`routines.ts` 为每位居民配置当前区域内的活动落脚点。居民隔几秒缓步挪动，停下后做手上的事，靠近玩家时暂停日常走动以方便交谈。动作起点错开，不会所有人同时抬手。日记、菜单和交谈打开时暂停。这些是表现层活动，不会自动赚钱、改变库存、传播消息或额外调用模型，实际跨区域移动优先于日常路线。

文字层直接在 Phaser 每个渲染帧中更新，和着色器使用同一份相机坐标；整层通过整数屏幕像素的 translate3d 平移，不再经过 React 异步调度或旧有的约30Hz位置更新。路牌元素持续保留，经过屏幕边缘不反复挂载。

本轮生产构建通过；实际浏览器连续100帧采样，文字层相机投影误差为0，路牌锚点测量误差小于0.001屏幕像素。跨方向走动时玩家仅使用正面行走帧0–5；居民站立时使用工作帧6–11，实测阿栗连续播放擦杯子动作。390px小屏无横向溢出，无页面脚本异常。居民日常动画和缓步活动在逻辑时钟不推进时也可继续播放。
