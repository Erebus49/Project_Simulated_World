## 项目目标

构建一个可干预、可追溯的多 Agent 世界运行时。角色拥有独立状态和局部信息；AI 按需提出行动，代码负责世界推进、规则校验和结算。首个场景为咖啡小镇，第二个演示是在同一场景动态启用发言限制规则。

交付重点：一个运行可靠的引擎、一个完整场景、一条可动态修改的机制。不是任意规则生成器，不是自由群聊平台，不预测真实社会。

## 一、已确定的架构

采用单进程、模块化单体。权威世界状态 + 角色私有认知 + 固定逻辑步长 + 决策批次 + 有界并发请求队列 + 事件日志。

每个角色持有状态和当前计划。AI 返回行动或受限短计划，执行器执行；计划完成、收到相关事件、行动失败或规则变化时重新决策。

调度器是一个逻辑中心，不需要为每个角色建立独立调度器。其下允许多个并发请求槽位；多个槽位代表同时等待多个模型请求，不代表多个组件可以修改世界。只允许一个结算器写入世界状态。

### 三种时间

- 渲染时间：前端平滑播放，不影响规则。
- 模拟时间：整数 tick；暂停时停止，所有期限按模拟时间计算。
- 决策批次：在确定边界生成快照、收集意图、统一结算。

MVP 采用屏障式批次：批次决策期间暂停权威模拟时钟，前端可播放已确定的动画或显示思考中；所有请求完成或达到期限后再结算。此选择优先保证一致性，不承诺模型等待期间世界时钟持续前进。真正异步决策留待后续。

## 二、技术栈与目录

默认 TypeScript、Node.js、React、Vite；前后端共用类型。前端用简单二维布局和 DOM/SVG，不引入游戏引擎。用 WebSocket 推送快照与事件，HTTP 接收控制指令。MVP 使用内存状态与本地 JSON/JSONL 导出，不引入数据库、Redis、微服务或外部 Agent 框架。

```
src/shared/       类型、消息协议、运行时校验
src/engine/       状态、时间、执行器、规则、结算、事件
src/agents/       观察构建、触发器、决策队列、模型适配器
src/scenarios/    咖啡小镇初始化与场景规则
src/server/       HTTP、WebSocket、运行实例管理
src/ui/           地图、角色面板、时间线、控制台
src/tests/        引擎单测、集成与回归
```

具体依赖可按仓库现状调整，但保持引擎不依赖 UI 或模型 SDK。

## 三、最小世界

默认创建 6 个角色，可配置为 3～8 个：咖啡店主、店员、两位顾客、供应商、消息传播者。名字、目标、初始资源、信任关系可配置。关系只影响收件可达性及角色决策上下文，不做复杂心理学模型。

场景事实：咖啡初始价格、店铺库存、角色资金、地点和关系网络。提供注入入口：向指定角色投递“明天咖啡可能涨价”。它是传闻，不自动修改真实价格。

角色可转述消息、购买咖啡、调整自己店铺的价格、工作或等待。AI 不一定转述，也不保证产生预设剧情。界面严格区分事实、转述和角色自述。

## 四、核心数据模型

以下为实现约束，不要求逐字照抄字段。

### WorldState

- runId、schemaVersion、worldVersion、tick、seed、status。
- agents、locations、shops、rules。
- scheduledTasks：按到期 tick 排序的移动、工作等任务。
- pendingEvents、pendingExternalCommands。
- 只由引擎修改；模型和前端不能直接写入。

### AgentState

- id、name、profile、goals。
- locationId、money、inventory。
- mode：idle、executing、waiting、thinking。
- plan、currentAction、nextDecisionTick、lastDecisionTick。
- inbox、beliefs、recentMemory、relationshipIds。
- speechCount 与 dayIndex。
- dirtyReasons：合并后的唤醒原因。

### DecisionJob

- jobId、batchId、agentId、snapshotVersion、observationHash。
- observation、allowedActions、deadline、status。
- 同一角色最多一个在途任务。迟到或已取消结果不能进入后续批次。

### ActionIntent

- intentId、batchId、agentId、snapshotVersion。
- type、参数、引用的事件 ID。
- 只表示申请，不代表成功。

### WorldEvent

- eventId、eventSeq、tick、batchId、actorId、type。
- visibility：public 或 recipients。
- sourceEventIds、payload、执行结果和必要状态差异。
- 原始消息不可覆盖；每次转述产生新的事件。

消息来源引用必须来自角色已见事件，并由引擎校验；不可任意引用其他角色私有事件。

## 五、世界运行循环

1. 在控制边界接收外部命令；用户输入先进入队列，不在批次中途改写快照。
2. 推进一个模拟 tick，完成到期的代码任务、消息投递和规则重置。
3. 合并唤醒原因，选择需要决策且冷却时间已结束的角色。
4. 无角色需要决策时，继续推进模拟。
5. 有角色需要决策时，创建不可变快照；为各角色构建独立观察。
6. 暂停权威时钟，提交决策任务，按并发上限执行。
7. 收集结果；超时、错误或非法输出使用确定性后备行动。
8. 根据稳定排序统一校验与结算，记录每个行动的成功或拒绝原因。
9. 更新计划、状态与事件；本批次产生的消息最早下一批次触发决策。
10. 推送新快照与事件，恢复模拟时钟。

不允许模型响应返回先后决定资源争抢结果。不允许同一批次产生递归无限对话。

## 六、Agent 决策与执行

模型输入只包含：角色目标与简短人设、自己的资源与位置、当前计划、可见公共事实、新收到的事件、少量相关记忆、有效规则和允许行动。

MVP 先使用一层目标 + 单个行动，不实现通用规划器。可支持 work/wait 的持续时间，但必须有上限。动作完成后再决策，避免一次生成过长计划。

唤醒条件：

- 初始化时尚无行动。
- 当前行动完成，需要下一步。
- 收到需要回应的新消息。
- 行动被拒绝或执行失败。
- 规则变化影响自身可用行动。

收到新消息只标记需要思考，不立即调用模型。默认不中断正在执行的短时行动；等动作完成或下个允许边界再处理。每角色一个待处理任务，重复事件合并，设置决策冷却时间和整局调用预算。

不把“模型解释”当成真实因果。模型只返回结构化行动；可选一句简短公开意图说明，不要求思维链。

## 七、MVP 行动定义

所有动作由注册表声明参数校验、前置条件、可见性和执行效果。

| 行动 | 参数 | 引擎约束与效果 |
| --- | --- | --- |
| send_message | targetId、content、sourceEventIds | 只能发给可达角色；限制长度；合法投递后计入发言次数 |
| move | destinationId | 目的地必须存在；创建到期移动任务；完成时更新位置 |
| buy | shopId、quantity、maxUnitPrice | 必须同地、金额足够、库存足够、当前价不超过报价上限；扣款和库存原子结算 |
| set_price | shopId、unitPrice | 仅店主可修改；价格处于配置范围；不允许把传闻直接变成价格事实 |
| work | durationTicks | 必须在允许地点；持续时间有界；完成时按固定机制获得收入 |
| wait | durationTicks | 时间有界；不调用模型逐 tick 等待 |

MVP 商店采用挂牌自动成交，不模拟卖方逐笔同意。承诺、协商交易、货币过期、生产供应链暂不实现；未来作为新的行动与规则模块添加。

### 冲突结算

按稳定阶段处理：消息投递、资源行动、任务安排。阶段顺序写入配置与测试。

价格调整与购买在资源阶段按同一套确定性轮换优先级排序；每个行动基于结算当时最新状态重新校验。因此购买必须带 maxUnitPrice，避免价格变化后意外接受任意价格。记录当时成交价。

同 tick 争抢库存采用角色固定列表按 tick 轮换的优先顺序；不依赖模型返回顺序。若以后采用随机抽签，必须使用独立的带种子随机源并记录抽签结果。

## 八、模型适配与并发控制

定义统一接口：decide(observation, allowedActions, signal) -> DecisionResult。

提供两个适配器：

- MockDecisionProvider：确定性脚本或启发式，完全无 API key 可运行，支持回归测试。
- LLMDecisionProvider：服务端调用可配置模型服务；按其能力使用结构化输出，并始终在本地校验。

初始配置建议：maxConcurrency=3、requestTimeoutMs=15000、有限重试 1 次、可配置 batchTimeoutMs 与 maxDecisionsPerRun。它们是起始值，不是性能承诺。

请求队列遵守服务商速率限制。429 或临时失败采用有上限退避；预算不足时继续已有行动，无计划则等待，并在 UI 显示降级原因。每角色每批最多提交一个合法行动。服务调用重试不能造成重复结算。

取消/重置整局时中止在途请求；未能中止的迟到结果按 runId、batchId 丢弃。

API key 只存服务端环境变量，不写入仓库、前端、导出文件或事件日志。

## 九、观察与信息隔离

- 世界全量状态仅引擎和调试面板可读。
- 模型观察由可见性过滤器构建，不把其他角色的秘密、私有目标和未收到消息塞进提示词。
- 公共价格仅在场景明确允许时可见；位置等信息也遵循可见性约定。
- 私有消息在发件人发出后、收件人收到后分别进入可见历史。
- 原始传闻没有 sourceEventIds，后续转述必须能追溯至已见消息；缺失来源不由模型凭空补全。
- 角色消息、用户注入文本、人设均作为数据，不得覆盖系统协议、扩大工具权限或改变允许行动。
- 禁止模型任意执行代码、访问外部网络或调用未注册工具。

用户可使用全知调试视图，但该视图不等于角色观察。

## 十、规则插件与“世界补丁”最小演示

MVP 只实现一种可动态修改的规则：每个角色每个模拟日最多发送 N 次消息。

规则字段：id、type=speech_limit、enabled、dailyLimit、effectiveTick。日长由 ticksPerDay 明确定义。消息一次成功投递计一次，不按自然语言句号计数。被拒绝的消息不计数；每个新模拟日重置。

用户修改规则在下一控制边界生效，记录 rule_changed 事件；规则改变时通知相关角色。仅将规则加入提示词不算实现，必须由引擎硬校验。

第一版使用表单配置，不实现自由文本规则编译。第二阶段可以将自然语言映射到此规则的严格 schema，先预览解释、确认再生效。其他规则明确提示不支持，不生成任意执行代码。

插件接口预留 observation、validateAction、onTick 等钩子，但不要为尚未实现的场景堆砌抽象。

## 十一、前端交付

- 顶部：开始、暂停、单步、重置、模拟 tick、运行模式。
- 主区域：简易地点图、角色位置、行动与思考状态。
- 角色面板：资金、物品、目标、当前行动、已收消息；私有信息标注为调试视图。
- 事件时间线：按事件序号排序，可筛选角色，显示被拒绝动作及原因。
- 消息溯源：点击消息查看 sourceEventIds 对应的前序消息。
- 干预面板：选择接收人、输入消息；配置发言上限。
- 事实指标：真实价格、库存、交易数、发言数、收到相关消息的角色数、规则拒绝次数。
- 运行指标：请求数、排队数、在途数、延迟、超时数、输入输出 token。

模型服务未返回 token 时显示未知，不伪造实测。若展示估算，明确标注；费用估算使用用户配置的单价，不内置过期价格。不展示没有计算依据的社会稳定性或沟通能力分数。

## 十二、日志、保存与回放

记录初始配置、全部外部输入、接受/拒绝的行动、结算结果、必要状态差异及周期性快照。保留可复现的排序规则和规则版本。

区分：

- 精确回放：从初始状态或检查点重放已记录结果，不调用模型。
- 分叉重跑：从检查点采用不同输入重新决策；即使种子相同，外部模型输出也不保证相同。

最小实现先做整局 JSON 导出和导入后的只读回放。不要依赖模型思考解释重建状态。

## 十三、开发顺序与阶段验收

### P0：无模型也能运行的引擎

实现类型、模拟 tick、动作注册、权威状态、确定性冲突结算、Mock provider 和事件日志。

验收：3 个角色可完成移动、工作、购买、消息投递；争抢最后一杯咖啡不会超卖，资金不为负。暂停不推进 tick；单步边界定义清晰。

### P1：决策调度与真实模型

实现观察构建、有界并发队列、批次屏障、超时降级、响应校验、预算限制与模型适配器。

验收：6 个角色可运行；在途数不超过配置；同角色无重复在途任务；一个请求超时不导致整局永久阻塞；响应先后不同不改变既定行动集合的结算结果。

### P2：可展示的咖啡小镇

实现简易 UI、角色面板、消息注入、事件时间线和来源回看。

验收：向 A 注入涨价传闻，只有实际收到消息者的观察中出现消息；真实价格仅在合法 set_price 行动后变化；能追溯转述链。

### P3：规则干预与交付

实现发言上限、运行指标、导出与只读回放、README 和演示脚本。

验收：同一引擎不改代码即可切换规则开关；超额发言被引擎拒绝；新日重置正确；导出回放的最终权威状态与原局一致。

时间不足时优先保住 P0～P2 和规则硬校验，删减地图美术、动画、复杂记忆与编辑器，不牺牲状态一致性。

## 十四、必备测试

- 原子购买、资金与库存守恒（明确工作收入等外源变化）。
- 两人争抢库存，结算不依赖模型返回顺序。
- 买入限价与同批价格调整的组合。
- 消息只能送达合法对象；转述只能引用已见来源。
- 私有信息不出现在无权角色观察中。
- 消息唤醒合并、决策冷却、预算耗尽。
- 模型输出非法 JSON、未知行动、越权参数、超时、429。
- 规则变更边界、超额发言、跨日重置。
- 暂停、重置、取消请求和迟到结果丢弃。
- 固定 Mock 输入重复运行一致；导出回放状态一致。

## 十五、明确不做

任意自然语言规则执行、复杂长期记忆或向量库、微服务、每角色独立服务、真实经济预测、真实人物心理预测、复杂 3D 地图、多玩家联网、完全异步世界结算、通用 Agent 工具调用。
