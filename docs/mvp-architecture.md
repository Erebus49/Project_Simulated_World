# 雾港纪事 MVP：实现与验证

实现日期：2026-10-16。本文描述当前代码，而不是后续路线图。

## 一个回合怎样发生

```mermaid
flowchart LR
  A[读取世界与版本] --> B[为每个角色生成过滤观察]
  B --> C[五个角色分别提出行动]
  H[可选真人行动] --> C
  C --> D[按敏捷执行并检查条件]
  D --> E[服务端骰点与状态更新]
  E --> F[GM 叙述已生效事件]
  F --> G[版本检查后写入 SQLite]
  G --> I[按观察视角返回世界]
```

`POST /api/worlds/:id/turn` 读取同一份不可变快照，并并行请求角色决策。每个角色每轮只能提出一个结构化动作：移动、调查、交谈、分享、安抚、休整或封印。真人接管时只替代该角色的本轮决策，其他角色照常行动。

`resolveRound` 克隆上一状态，再按敏捷从高到低执行；敏捷相同时按固定角色顺序。每次动作执行前重新检查地点、目标、精力与知识。一次无效的模型提案成为该角色可见的中断事件，不会让模型直接修改世界。

每个事件携带发生地点、可见角色集合、是否私有以及可选检定。事件只写入目击者的记忆。角色保存最近 80 条记忆，决策请求使用最近 18 条；当前没有向量检索、摘要反思或长期计划模块。

模型模式先由五个角色分别调用模型，再由 GM 调用模型组织叙事；GM 收到已裁决事件和前文，不能通过返回 JSON 改写规则状态。本地模式使用相同观察结构与确定性的角色策略，骰点仍然随机。

GM 完成前，新的世界只存在于内存。角色请求失败、响应格式错误或 GM 叙事失败时，丢弃新状态，保留原存档并发送错误。成功才进行带预期版本的 SQLite 更新，再发出完成事件。

## 角色知道什么

| 信息 | 角色模型 | 角色界面 | 导演界面 |
| --- | --- | --- | --- |
| 自己的人物卡、秘密、个人目标 | 有 | 有 | 有 |
| 其他人的公开目标 | 同地点可见 | 有 | 有 |
| 其他人的秘密、个人目标、记忆、线索集合 | 无 | 无 | 有 |
| 所有地点与通路 | 公共地图 | 公共地图 | 有 |
| 其他人的实时位置 | 仅同地点角色 | 同地点可见，其他显示未知 | 有 |
| 自己掌握的线索 | 有 | 有 | 有 |
| 未发现的线索正文 | 无 | 无 | 有 |
| 同地点的公开动作 | 通过记忆获得 | 有 | 有 |
| 私有分享的正文 | 仅发送者与接收者 | 仅参与者 | 有 |
| 导演全知叙事 | 不传入角色上下文 | 用可见事件替代 | 有 |

角色界面保留公开的人物性格、属性和生命 / 理智数值。它不是隐匿所有动态信息的战争迷雾系统。完整备份、切换导演及编辑人物是本机导演功能，不构成多用户鉴权边界。

角色可以把任意内容写入台词，但台词不会赋予线索或改变判定结果。正式知识传递必须使用「分享」动作。需要自然语言对话自动抽取知识时，应另外定义抽取与验证协议；当前没有把一句“我告诉了他”当作知识状态更新。

## 决策与角色差异

`demoDecision` 只接收 `Observation`。低理智时休整、掌握足够线索后前往灯塔、保护型角色优先安抚、守护型角色先建立信任、利益型角色优先码头、社交型角色主动传递消息。已分享与否由自己记忆判断，不读取对方的隐藏线索。

本地策略主要参考行为倾向和自己的状态。用户编辑的文字人格、公开与私人目标会完整传入模型模式，本地策略不会理解任意自然语言设定。私有目标目前是角色决策资料，不是独立胜利积分系统。

## 数据与失败处理

- 世界按 JSON 存入 SQLite，另存版本、标题、回合等索引字段；设置使用独立表。
- 每个世界有执行锁，阻止同进程中的重复推进或推进中编辑；数据库更新同时检查旧版本，防止较旧客户端覆盖新状态。
- 对前端使用 NDJSON 进度流，发送阶段、每个角色的思考状态、完成世界或错误。进度不会包含角色尚未执行的私有提案。
- 备份导入校验版本、人物 ID 唯一性、线索引用、数值边界、回合连续性与结局一致性；创建新 ID，不覆盖原战役。
- 模型错误只返回已清理的信息，API Key 不出现在设置响应、世界、战报或备份中。用户输入的密钥由浏览器提交后存于本机 SQLite，不采用加密存储。
- 断开浏览器不会主动撤销正在处理的回合；服务器可能继续完成保存。再次打开时以 SQLite 为准。前端检测到不完整进度流时会提示刷新确认。

## 已完成的验证

| 验证层 | 当前结果 | 实际验证内容 |
| --- | --- | --- |
| TypeScript / 生产构建 | 通过 | 共享类型、服务端、前端、测试配置和 Vite 构建 |
| 引擎、存储与 API | 20 项通过 | 观察隔离、骰点、移动、私有线索、失效互动、终局、不可变旧状态、备份、重启恢复和并发 |
| 模型兼容 HTTP | 包含于上述测试 | 本地模拟服务收到五份不同角色观察，再收到一份 GM 请求；测试角色和主持人错误回滚 |
| 实际 Chromium | 7 项通过 | 编辑、接管、视角、回放、刷新、自动演绎、暂停、结局、导入导出、设置与错误恢复 |
| 窄屏 | 375 × 812 通过 | 手机地图与人物操作、接管表单；页面无水平溢出，无未捕获 JS 异常 |

额外运行了 100 次带种子的本地 d20 模拟，均能在十二轮内进入明确终局，其中 93 次封印成功、7 次失败。这只是当前场景的流程检查，不代表语言模型的成功率或故事质量。

第三方模型的实际输出质量、服务可用性、费用和不同服务商兼容性尚未用真实密钥验证。调研中的其他项目仅做静态源码和文档核实，没有以本项目测试结果替它们背书。
